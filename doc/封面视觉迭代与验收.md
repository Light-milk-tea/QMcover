# 封面视觉迭代与验收

适用于按参考图新建模板，以及用户要求“更像、更好看、继续打磨”的现有模板。构图与内容约束见 [按参考图生成模板](模仿参考图生成模板.md)，工程接线见 [TEMPLATES.md](../TEMPLATES.md)。这里记录改变设计判断和验收结果的具体方法。

## 先建立可比较的画面

- 选定主参考，在 `references/<系列>/INDEX.md` 记录原图尺寸、来源、文件名及借鉴范围。实际打开图片，不只读 INDEX：文字备忘也可能写错。
- 把参考图与当前画布以相同宽高查看，例如都缩到 960×540。不同尺寸会让字号、人物大小和边距比较失真。16:9 原图不用额外中心裁切。
- 同时看全图和关键局部。全图判断阅读顺序、明暗块、留白；局部判断字形、轮廓、渐变与光痕。最终以封面缩小后的辨识度为准。
- 记录人物脸部、主标题、人数、条件等的可见边界和相对位置。参考坐标可用 `x / 原图宽`、`y / 原图高` 换算到 1920×1080；CSS 字号与元素盒子不等于实际字形高度，仍需看截图。

## 每轮围绕一个主要差距改

先写一句“参考图是什么、当前哪里不同、这轮改什么”，再动手。优先级如下：

| 顺序 | 比较对象 | 常见误差与调整方向 |
| --- | --- | --- |
| 1 | 构图与阅读顺序 | 人物和标题占比不对、辅助信息抢眼；先改位置、尺寸、遮挡关系。 |
| 2 | 明暗与人物融合 | 脸灰、白发过曝、下半身突然消失；分别检查调色、局部遮罩和渐隐范围。 |
| 3 | 字形与字级 | 字体相近但粗细不对，数字压倒中文；分别匹配标题、条件、数字、单位。 |
| 4 | 材质与色散 | 参考是局部晕染，当前却是整齐描边；调整颜色的分布、遮罩和偏移范围。 |
| 5 | 光效与装饰 | 参考有疏密、断续、远近，当前是均匀直线；保留方向关系，减少机械重复。 |

保留修改前截图，再获取修改后截图，比较这轮假设是否成立。变差就回调该项，不要靠新增一层特效掩盖。主要差距还在时继续；默认构图、文字适配、编辑器和实际导出都过关后结束。无需为了凑轮数改已经合适的层。

视觉迭代次数与浏览器测试失败重试是两回事；测试仍遵守仓库的 Vitest Browser 技能。用户明确的风格选择优先于这里的案例。

## 材质做法及其边界

- **先保轮廓，再加氛围。** 脸和发丝保留亮部细节，身体向场景过渡；不要整屏加红/黑遮罩。看清立绘自带的场景、光照和装饰，避免额外背景与它争夺注意力。
- **按区域做色散。** 若参考字上部明亮、下部染色，保住白色主体，在字底和少数局部放青红偏移。整字大幅复制会像粗描边，多个横向切片会像规则故障条。
- **不规则不等于随机堆砌。** 少量 SVG 曲线、断续光痕可配固定 seed 的 `feTurbulence` / `feDisplacementMap`，雾带可轻微模糊。先定方向和疏密，再加扰动。不要每次渲染生成随机形状，导致预览、导出不同。
- **噪点要在目标尺寸检查。** 重复的小圆点缩小后可能显成网格。先减弱强度，不要把颗粒当作通用“高级感”开关。
- **字体要看实际加载结果。** 只有 700/900 字重的字体即使写 300，也不会凭空得到真正细体。需要细数字时可选合适衬线字体；系统字体跨平台可能不同，必须检查实际 Chromium 字形，要求一致时使用项目可用的对应字体资源。
- **装饰层和编辑层各司其职。** 字效放内层真实 DOM，外层 `CoverElement` 保留拖动语义；SVG filter id 用实例唯一值（例如 `useId`），避免多个模板同时挂载时串用。
- **CSS 支持不等于导出支持。** 多重渐变、`background-clip: text`、mask、滤镜都要查看实际导出；验证某一组合成功，不应推广成所有滤镜都可靠。

## 三个视图都要验收

| 视图 | 目的 |
| --- | --- |
| `#/__thumb/<id>` 默认稿 | 检查默认构图及首页缩小后的辨识度。 |
| `#/t/<id>` 整页编辑器 | 检查有编辑上下文时的图层顺序、覆盖值、拖动与文字修改。 |
| `html-to-image` 实际输出 | 检查文字、图片、遮罩及纹理是否完整。浏览器截图不能替代这项。 |

### 截图前等图片解码

使用项目已有 Playwright Chromium。`img.complete && img.naturalWidth > 0` 只说明资源已加载，`decoding="async"` 的图片此时仍可能没有绘制。先等目标画布出现，确认预期图片确实存在，再等待 `decode()`；不能让“空图片列表的 every 返回 true”误判成加载完成。

以下片段用于有背景和立绘的默认稿；其他模板按实际预期图片数量调整。`page` 为已经打开目标路由的 Playwright 页面：

```js
const canvas = page.locator('[data-emergency-lesson-canvas]');
await canvas.waitFor({ state: 'visible' });
await page.evaluate(() => document.fonts.ready);
await canvas.evaluate(async (el) => {
  const images = [...el.querySelectorAll('img')];
  if (images.length < 2) throw new Error('默认背景或立绘尚未挂载');
  await Promise.all(images.map((img) => img.decode()));
  if (images.some((img) => img.naturalWidth === 0)) {
    throw new Error('画布图片未成功解码');
  }
  await new Promise((resolve) => {
    requestAnimationFrame(() => requestAnimationFrame(resolve));
  });
});
// 此后截图；如果资源切换或解码失败，先检查资源状态，不要保存空白图当成完成。
```

字体和图片出现异常时先诊断加载/解码，不要立刻改滤镜、层级或删除遮罩。不要用固定 sleep 冒充就绪条件。

### 实际导出与缩略图

- 最终执行编辑器的 PNG 导出并查看文件。快速迭代还可读取 `ThumbCapture` 提供的 `window.__QM_THUMB`：先确认不是 `error:`，再解码保存；这是 `html-to-image` 的 JPEG 输出，不应称为 PNG 验证。
- 本次紧急授课实际检查了上述 JPEG 输出与 Chromium 截图，不能把该记录写成已经验证过 PNG 导出。
- 字效或遮罩不一致时，缩小问题到对应层并调整后重导。不要用截图替换导出文件来掩盖问题。
- 定稿后把生成的模板缩略图转换为 960×540 WebP，同时更新 `public/thumbs/<id>.webp` 和 `src/assets/thumbs/<id>-shot.webp`；新模板还需接入 `src/lib/thumbs.ts`。可使用浏览器 canvas 转 WebP，不必为临时转换新增 sharp。
- 原始参考图、下载的立绘和 AVG 不提交；生成的模板缩略图按仓库既有方式维护。过程截图可放临时目录，长期经验用本文和源码说明，不依赖 `/tmp` 的文件存续。

### 文字适配与默认值

- 浏览器测试覆盖默认文案以及更长的标题/条件。检查可见标题右边和底部的安全余量、条件与人数之间的关系，不能只测文字存在或 span 数量。
- 字数分段规则也可能越界：紧急授课原来的 9 字标题字号 206 在实测中超出了画布。根据可用宽度调整缩放后重新测，不放宽边界断言。
- 同步模板组件、`src/data/seeds/`、模板元数据中对应的默认值；全局效果默认在 `src/lib/effects.ts`，只调整目标模板所需的分支。
- 旧草稿会保存自己的字号、位置、立绘调色和全局效果。新默认不会自动替换这些值；不要为展示新效果清空用户的 `localStorage`。分别检查新稿和旧稿，确需迁移时仅迁移明确的旧默认，保留自定义内容。

## 案例：紧急授课

主参考：[黑蓑影卫攻略组索引](../references/black-cloak/INDEX.md)，图为 `01_BV1xEkmYsEog.jpg`（1600×900）。实现：[EmergencyLesson.tsx](../src/templates/EmergencyLesson.tsx)。这是单图案例，不应声称已经确认整个 UP 系列的不变量。

| 观察到的差距 | 最终采用的改进 |
| --- | --- |
| 初版位置接近，但线条规整，像技术示意线 | 用有方向、断续的不规则紫色光痕和疏密变化的弧线，减少机械重复。 |
| 立绘上罩红、人物下半身淡出太早 | 减轻局部遮罩，延长下半身可见范围；适度调色后再收回过亮的高光。 |
| 标题青紫重影像完整描边 | 白色主体保留，字底局部染色，重影加渐隐/局部裁切，雾带降低强度。 |
| 人数、条件、标题互相争夺注意力 | 分别选择粗宋体标题、较细条件与数字，重新对比三者尺寸和锚点。 |
| 缩略图有图，编辑器截图一度无立绘 | 确认图片已加载后继续等待解码与绘制；最终显示正常，无需为此改产品图层。 |

这次最有用的经验：第一版“结构像”之后，还要对照亮暗关系、字形和材质分布。逐轮截图暴露了纯读代码看不出的差异；实际导出避免把只在浏览器中好看的效果当成最终成果。
